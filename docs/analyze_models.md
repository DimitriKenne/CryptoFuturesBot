# How to Interpret Model Analysis Results

**Author:** Dimitri Kenne
**Date:** 2025-08-22

This guide explains how to interpret the various plots and data files generated by the `analyze_model.py` script. Understanding these results is the most important step in improving your trading model.

---

### 1. Evaluation Metrics (`evaluation_metrics.json`)

This file contains the raw performance numbers for the model on the test set.

-   **`overall_accuracy`**: This is the percentage of correct predictions out of all predictions. **Warning:** This metric is very misleading for imbalanced datasets. A model that always predicts the majority class (e.g., 'Hold') will have high accuracy but is useless for trading.
-   **`balanced_accuracy`**: This is the average of recall scores for each class. It is a much better indicator of performance on imbalanced data. For a 3-class problem (Buy, Sell, Hold), a score of **33.3% is equivalent to random guessing**. Your goal is to get this number as high as possible.
-   **`classification_report`**:
    -   **`precision`**: Of all the times the model predicted a certain class, how often was it correct? (e.g., "Of all the 'Buy' signals, how many were actually buys?")
    -   **`recall`**: Of all the actual positive instances, how many did the model correctly identify? (e.g., "Of all the true 'Buy' opportunities, how many did the model find?")
    -   **`f1-score`**: The harmonic mean of precision and recall. It provides a single score that balances both concerns.

---

### 2. Confusion Matrix (`confusion_matrix.png`)

This plot is a direct visualization of the model's predictions versus the actual outcomes.

-   **What to look for**: An ideal model would have high numbers along the diagonal (top-left to bottom-right) and low numbers (ideally zero) everywhere else.
-   **Interpretation**: This plot immediately reveals if the model is biased. If you see a very large number in the center (for class '0') and very small numbers for classes '-1' and '1', it confirms the model is mostly ignoring the Buy/Sell signals and just predicting 'Hold'.

---

### 3. Feature Importance (`feature_importance.png` & `.csv`)

These files show which features had the biggest impact on the model's decisions.

-   **What to look for**: The plot and CSV show a ranked list of the most influential features.
-   **Interpretation**: This is one of the most actionable outputs.
    1.  **Sanity Check**: Do the top features make logical sense for trading? (e.g., volatility, momentum, price action features).
    2.  **Feature Selection**: If the model is not performing well, you can try re-training it using only the top `N` features (e.g., top 30 or 40). This can reduce noise and sometimes improve performance.

---

### 4. ROC AUC Curve (`roc_auc_curve.png`)

This plot shows the model's ability to distinguish between classes.



-   **What to look for**:
    -   **The Curve**: A good model has a curve that pushes towards the top-left corner. A curve along the dashed diagonal line represents a model with no skill (random guessing).
    -   **AUC (Area Under the Curve)**: This is a single score summarizing the curve. **1.0 is a perfect score**, while **0.5 is a random guess**.
-   **Interpretation**:
    -   Look at the AUC for each class individually. In your case, the AUC scores for classes -1, 0, and 1 were all between 0.55 and 0.60, indicating the model has very little skill.
    -   Ignore the "micro-average ROC" score in an imbalanced dataset, as it is artificially inflated by the majority class.

---

### 5. Calibration Curve (`calibration_curve.png`)

This plot shows how trustworthy the model's predicted probabilities are.



-   **What to look for**:
    -   **Top Plot (Reliability Curve)**: A perfectly calibrated model would have its lines run along the dotted diagonal.
    -   **Bottom Plot (Histogram)**: Shows the distribution of predicted probabilities.
-   **Interpretation**:
    -   If a line is **below** the diagonal, the model is **over-confident**. (e.g., it predicts 40% probability, but the event only happens 20% of the time).
    -   If a line is **above** the diagonal, the model is **under-confident**.
    -   Your calibration plot showed the model was severely **over-confident** on its Buy/Sell predictions. The histogram also showed that it was rarely confident in these predictions, assigning them low probabilities.

### Conclusion: How to Improve the Model

Based on a typical first-run analysis, the key problem is **class imbalance**. The model learns to predict the 'Hold' signal because it's the safest bet to achieve high accuracy. Your goal is to force it to learn the rare 'Buy' and 'Sell' signals.

**Actionable Next Steps:**

1.  **Enable Hyperparameter Tuning**: Run `train_model.py` but **remove the `--skip_tuning` flag**. This is the most important first step.
2.  **Experiment with Class Balancing**: In `config/model.py`, find the `class_balancing` parameter in `XGBoostParams` or `RandomForestParams` and change it from `None` to `'undersampling'` or `'oversampling'`.
3.  **Feature Selection**: Use the `feature_importance.csv` to re-train the model on only the most powerful features using the `--features` command-line argument.
